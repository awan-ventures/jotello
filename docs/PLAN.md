# Jotello — native macOS visual feedback utility

Status (2026-10-18): P0 steps 1–5 are implemented and unit-tested. Step 6, the manual acceptance pass on real apps, is pending; see [TESTING.md](TESTING.md). P1 is next.

Decisions made while building P0:
- The composer is a fixed 300-point panel on the right of the editor window, not a floating panel.
- The App Sandbox is off (direct distribution, not the App Store), so captures are saved to `~/Library/Application Support/Jotello/Captures/` with a normal absolute path an agent can open.
- App and window names come from the system window list under the selection's center, read before the overlay appears. There is no browser DOM or URL access.
- A long issue description (over 6,000 characters) is left out of the URL and copied to the clipboard instead.

## One-line promise
Select something on your screen, mark what should change, then hand an agent-ready report to your existing workflow.

## Non-negotiable UX
- Lightweight macOS **menu-bar** utility. **Single-click** menu-bar icon enters native region-select mode; optional keyboard shortcut.
- Select any visible screen region across browsers, desktop apps, localhost, staging, and production. **No built-in browser**.
- Annotate screenshot with lightweight arrow, rectangle, text; support undo, cancel, copy.
- Compact composer opens after selection: **title (optional/autogenerated), description, label/type** (Bug, UX improvement, Polish, Other), optional source URL, and destination.
- Remember last destination and repository/PR URL; don't force login for first use.
- **Default handoff**: copy screenshot to clipboard and formatted feedback text separately (or paste-ready bundle where receiving app permits), open prefilled destination in user's browser when possible. Users confirm and paste/upload; **do not claim screenshot has been attached remotely**.
- Destination adapters: GitHub New Issue; GitHub PR conversation URL (opening existing PR and copy feedback), Jira issue create, Trello card create, generic clipboard for Claude Code/Codex/terminal. Distinguish what each website genuinely supports by URL prefilling; fallback to open page + clipboard. Avoid unofficial automation or brittle URL assumptions.
- Optional selected PR/issue association and page URL stored with capture; don't infer relation between localhost and PR.
- Keep the app private, local-first, and usable offline for copy.

## Foundation and licensing
Evaluate [jo9900/snaplet](https://github.com/jo9900/snaplet) (MIT, Swift/AppKit/SwiftUI, macOS 14+, capture, arrows, shapes, text, undo/redo, clipboard). Check baseline build/tests, code quality, license and upstream provenance before fork. **Do not erase MIT copyright attribution**. Native app implementation should live in a **separate public Jotello repository**, not as an `apps/<slug>` static web app here. Made by Awan is the planning and portfolio index.

## Architecture
- Screenshot region selection and annotation: reuse upstream capture/editor as much as possible.
- `FeedbackDraft`: versioned local representation (id, timestamps, screenshot file path, annotations, title, description, category, app/window name when permitted, optional user-provided URL, selected destination, repository/PR or issue URL).
- Screenshot and text export: PNG + Markdown/plaintext with readable heading, description, requested change, URL, capture dimensions and app/window context where permitted. Avoid claiming browser DOM access.
- `DestinationAdapter`: `buildText(draft)`, `prefillURL(draft)` if reliably supported, `openDestination(draft)`; always offer fallback copy + open. No service backend.
- CLI/agent workflow: **Copy instructions** and **Copy screenshot**, optionally save draft in a local directory or generate an export bundle with relative image path. Clipboard images do not always paste into terminal agents; include path references. Example: `Please address this UI feedback: ... Screenshot: /path/to/capture.png`. No MCP server in MVP.
- Browser metadata/DOM is **not available from pixels**. Optional later browser helper with consent could associate DOM selector, element HTML, CSS, bounds, viewport, URL and possibly source mapping. Avoid including private HTML or secrets in exports.

## Privacy and security
Screen Recording permission on macOS; explain why. Never capture in background without user action. Visible preview and explicit send/copy action. No telemetry or cloud storage. Avoid scraping secrets from screen automatically. Warn for sensitive screenshots before opening/public sharing. If GitHub API is added later, use secure auth and Keychain; never store tokens in plain preferences.

## Release slices
### P0 — usable local MVP
1. Upstream review, separate fork/repository, rename/icon/license, reproducible build on Apple silicon; establish smoke tests.
2. One-click menu bar capture, region selection, screenshot annotation.
3. Compact feedback composer with category, description, screenshot preview, cancel/edit.
4. Clipboard/save export: screenshot, formatted text, local image path, copy instructions for Claude Code/Codex.
5. GitHub issue-prefill and PR URL open + copy; generic destination and browser fallback.
6. Manual acceptance smoke test on browser localhost, Chrome, VS Code and a standard Mac app.

### P1 — destination quality
7. Jira and Trello launch/prefill adapters verified against current provider behavior; fallback to clipboard.
8. Saved destinations, defaults, repository/PR association, multiple captured annotations in one session.
9. Distribution: signed/notarized release, update path, privacy guidance, CI.

### P2 — deeper integrations (not MVP)
10. Optional GitHub authentication to create issues or comment on PRs directly, with honest screenshot upload strategy.
11. Optional Chrome companion for DOM and browser URL capture, with explicit permission/opt-in.
12. Agent automation or MCP only after clipboard handoff proves insufficient.

## Acceptance criteria
- Launch Jotello; single click on menu-bar icon; select region on any screen; annotate; type a short note and select Bug; copy in under a short interaction without a mandatory login.
- Open a GitHub issue creation page with supported prefilled fields, clipboard-ready report and locally available annotated PNG. User manually attaches screenshot.
- From pasted PR URL, open existing PR and copy a PR-comment-ready report. **Do not claim GitHub inline code review comments**.
- CLI flow outputs an absolute screenshot path and agent-readable task prompt, not merely image clipboard.
- No browser window inside Jotello; no remote server dependency; cancelling never posts anything.
- Upstream attribution, test instructions and no sensitive screenshot uploads without explicit action.

## Open questions to test, not blocking planning
- Whether to show composer as floating panel versus attached to capture overlay.
- Reliable URL prefill support varies by GitHub/Jira/Trello; build fallbacks first.
- Native context beyond active app/window and user-entered URL requires explicit exploration; don't promise DOM without companion.
- Estimate: **1–2 focused development days for an internal copy/paste prototype**, **3–5 focused days for a robust MVP** assuming Snaplet fork is healthy; more time for signing/notarization and edge cases. These are planning estimates, not delivery promises.
